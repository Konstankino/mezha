# ADR-0002. Команда хука: прямий виклик бінарника, fail-closed

- Статус: запропоновано
- Дата: 2026-10-07
- Приймає: автор проєкту

## Контекст

Розділ 3.3 плану вимагає прямого виклику `mezha hook <name>` без shell-обгортки і без sh-двійників. Принцип 3 (розділ 2) вимагає, щоб відсутність бінарника блокувала, а не пропускала.

Claude Code трактує коди виходу хука так:

- 0 — успіх;
- 2 — блок, і stderr стає причиною для Claude;
- будь-який інший код — неблокувальна помилка, тобто виклик інструмента виконується.

Голий `mezha hook …` без бінарника завершується з кодом 127 (command not found), а паніка Rust — з кодом 101. Обидва пропускають виклик. Отже, вимоги розділу 3.3 і принципу 3 разом, буквально, не виконуються.

ocgen розвʼязував це так: `if [ "$(ocgen hook --check)" = "<протокол>" ]; then ocgen hook X; else sh X.sh; fi`. Це два процеси на кожен виклик і двійники логіки на sh, а коли немає ні бінарника, ні скрипта, виклик проходить.

## Рішення

1. **Команда в `settings.json`**, з `"shell": "bash"`:

   ```
   mezha hook approval-gate --protocol 1 --gate 'git push' || exit 2
   ```

   Мінімальна обгортка `|| exit 2` перетворює 127, 101 і будь-яку іншу помилку на блок. Один процес, без sh-двійників. Будує цей рядок лише `mezha_hooks::command_line`.
2. **Контракт виходу.** `mezha hook` відповідає лише 0 («заперечень немає», без виводу) або 2 (блок, причина в stderr). Рішення `allow` хук не видає ніколи, тож правила `permissions.ask` і далі питають людину.
3. **Протокол і конфігурація в аргументах.** Номер протоколу передається як `--protocol N`; невідповідність — блок із підказкою запустити `mezha compile`. Хук не читає `mezha.toml`: гейти приходять аргументами `--gate`, а граматику `CommandPrefix` перевіряють і spec, і хук.
4. **Без `matcher`, на всіх інструментах.** Команди з `tool_input.command` (Bash, PowerShell, Monitor) перевіряються; шлях у `~/.mezha` блокується для будь-якого інструмента. Коли бінарника немає, блокується все: відмова гучна, а не тиха.
5. **Хук не запускає процесів.** Корінь репозиторію шукається обходом `.git` (для worktree — через `commondir`), бо таймаут хука Claude Code теж трактує як неблокувальну помилку.

## Наслідки

- `mezha` має бути на `PATH` на кожній машині, де Claude Code працює з цим проєктом, і в CI. Без неї кожен виклик інструмента блокується.
- Генерувати хук у репозиторії самої Mezha під час її розробки не можна: зламаний або відсутній бінарник заблокує власну сесію.
- `|| exit 2` працює в bash, sh і PowerShell 7. У Windows PowerShell 5.1 `||` — синтаксична помилка, і хук пропускає виклик. Тому native Windows до фази 4 лишається advisory, а `compile` поки відмовляє для `os_mode = "native-windows"`.
- Сам гейт `git push` — це матчер, тобто advisory. Межею є sandbox (`filesystem.denyWrite` для `~/.mezha`) і credentials, недосяжні з sandbox (фаза 1). Крім того, встановлений mod Claude Code може схвалити виклик, який заблокував хук, якщо хук не в managed settings. Це ще одна причина не вважати гейт межею.
